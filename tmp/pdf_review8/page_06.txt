3.3 System Requirements
A standard clinic workstation suffices for deployment: an Intel Core i5 (8th gen-
eration or later), 8–16 GB RAM, and, if available, an NVIDIA RTX 3050 GPU
for training – inference runs comfortably on CPU alone – with roughly 100 GB
of disk space for models, datasets, and cached embeddings. The software stack
requires Python 3.10 or later, CUDA 11.8 for GPU acceleration, and Streamlit
1.30 or later for the dashboard, running on Ubuntu 22.04 LTS or Windows 11.
4 System Architecture
4.1 Input Layer
The model accepts three categories of input.Topography imagesare the
colour-coded corneal maps already familiar to ophthalmologists, produced by
Placido-disc or Scheimpflug topography/tomography systems as JPG/PNG files,
encoding corneal curvature, elevation, and thickness as spatial colour gradients.
Spatial map gridscarry the same regional curvature and thickness informa-
tion as raw numerical arrays rather than a rendered colour map, letting the
network learn from the underlying measurements directly.Clinical measure-
ments (biomechanical indices)are the values an ophthalmologist would al-
ready record – corneal curvature (Ks, Kf, AvgK), pachymetry, elevation indices,
symmetry coefficients, and wavefront aberrations – effectively the cornea’s vital
signs. A deliberate design choice underlies this layer:missing inputs do not break
the pipeline. Any absent modality is zero-filled rather than causing a failure, so a
clinic can start using the tool productively even with an incomplete measurement
set, adding modalities as its equipment allows.
